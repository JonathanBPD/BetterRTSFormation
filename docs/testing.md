# 测试指南

本仓库**没有自动化测试**：没有测试源集，`build.gradle` 也没有注册任何自定义回归任务。质量保障靠 `deploy` 构建全链通过 + 发布前手测清单。改到对应功能时，至少跑一遍相关条目。

## 自动化部分

无。仅两条底线：

- `.\gradlew.bat deploy` 必须成功（编译 + dex + 打包全链）。
- 发布前按 [release.md](release.md) 核验合并 jar 含 `mod.json` 与 `classes.dex`。

若未来引入纯函数级逻辑（如键位解析），可考虑补 main() 断言式回归任务并接进 `test.dependsOn`；依赖游戏运行时的行为（输入、渲染）不写自动测试，走手测。

## 手测清单

环境：桌面客户端加载 `dist/BetterRTSFormation-<version>.jar`；聚合形态条目在 Neon 侧验证。键位按默认值描述，自定义键位需相应替换。

1. **加载与设置**
   - 模组正常加载（`hidden: true`，不加载游戏内容属正常）。
   - `设置 → 模组 → Better RTS Formation`：两个开关，`启用编队角标与严格编队选择` 默认开、`在非指挥模式也能控制编队` 默认关。
   - `设置 → 控制 → Better RTS Formation`：五个前置键齐全；「恢复默认」后为 左 Ctrl / 左 Shift / 未绑定 / 左 Alt / Delete，已有自定义键位不被强制覆盖。
2. **快捷键编队**（`brf-enabled` 开启）
   - 选中己方可指挥单位：左 Ctrl+数字 追加进编队，重复追加同一单位不产生重复成员；左 Shift+数字 覆盖创建；左 Alt+数字 整组选中并替换当前选择。
   - 排他前置键自定义绑定后：前置+数字 先把单位从所有编队踢出再加入目标编队。
   - 主键盘与小键盘 `1-9`/`0` 都生效；指挥模式 + 原生「创建编队」和弦 + 数字被拦截，不触发原版行为；配置了选择前置键时，指挥模式下裸按数字的原生选择也被拦截。
   - 点按 Delete（未按住追加键）把选中单位从所有编队踢出。
   - 只影响单位：选中内容混有可指挥建筑时，建筑不进编队；选择编队后建筑选择被清空。
3. **框选创建**（`brf-outside-command-mode` 开启且不在指挥模式）
   - 按住左 Ctrl 拖框：框选单位创建进第一个空闲编队，框的颜色为该编队颜色。
   - 按住排他前置键拖框：排他版框选。
   - 同时按住 左 Ctrl + Delete 拖框：红框，清除框内单位的所有编队。
   - 没有空闲编队时框选不执行；松开鼠标或松开前置键即完成；拖框期间原版框选输入被捕获。
4. **编队角标与聚团**
   - 成员单位左下角显示对应颜色的数字角标（1-9/0）；同一编队中相近单位聚成一簇后只显示一个编号，簇较大时编号适度放大。
   - 同编队的分散单位分别显示；不同编队即使相邻也不误合并；同一单位属于多个编队时编号按顺序横向并排。
   - 缩放镜头、移动单位和在视野边缘聚团时，编号仍可见且位置随簇中心更新。
   - 单位死亡/失效后编队自动剔除（再次编辑或寻找空闲编队时生效），角标不残留。
   - 视野外的单位不绘制；非己方队伍单位无角标。
5. **载荷运输后的编队保持**
   - 将已加入编队的单位交给 Mega、quad、oct 或其他可搬运单位，再释放到地图；释放后原编队号仍显示，按前置键+数字选择仍能选回。
   - 单位进入/离开 PayloadBlock、Payload Conveyor 等载荷建筑后同样保持；运输期间按选择编队、寻找空组、Delete 或覆盖创建，不应把暂时装载的成员误删。
   - 释放路径发生实体 ID 变化时，旧 ID 应迁移为新 ID；单位真正死亡/销毁后不得留下幽灵成员。
6. **开关与边界**
   - 关闭 `brf-enabled`：角标消失、快捷键与框选全部失效；重新开启后恢复。
   - 打开对话框/聊天/搜索框时按键不触发；切换地图后无残留框选状态。
7. **聚合形态（Neon）**
   - Neon 聚合包内 brf 的两个开关以 RbmStyle 图标开关渲染在 Neon 设置页，且**不**出现独立的「Better RTS Formation」设置分类。
   - 开关语义与独立形态一致，切换即时生效。
8. **安卓合并包**
   - 安装合并 jar 于安卓设备可正常加载（验证 `classes.dex`）；重点验证输入交互无 `AbstractMethodError`（拖框、按键）。
